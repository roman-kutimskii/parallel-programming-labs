# Лабораторная 3 — синхронизация доступа к общим данным

Потокобезопасный банк (`Bank`) и симуляция экономики поверх него. Участники —
Директор электростанции, Отец, Мать, Сын, Дочь и Продавец — переводят деньги со
счёта на счёт и из кошелька в кошелёк. После симуляции программа проверяет, что
деньги не потерялись и не появились из ниоткуда.

```
./build/lab03-bank/bank --mode <single|parallel> --seconds <N> [--quiet]
./build/lab03-bank/bank-tests
```

- `--mode single` — все участники ходят по очереди в одном потоке;
  `--mode parallel` — каждый участник в своём `std::jthread`.
- `--seconds N` — длительность; Ctrl+C останавливает раньше.
- `--quiet` — не печатать действия участников, только итог (для замеров).

Итог выглядит так (код возврата 0, если оба правила выполнены, иначе 3):

```
Режим: parallel, время: 3.00 с
Операций банка: 46466756, в секунду: 15484535
Сумма кошельков 3100 == наличные банка 3100: да
Наличные 3100 + счета 6900 == начальная сумма 10000: да
```

Тесты запускаются и через CTest: `ctest --test-dir build`.

## Устройство

| Файл | Что внутри |
|------|------------|
| `bank.h`, `bank.cpp` | `Bank` — счета и наличные под одним `std::mutex`, счётчик операций — `std::atomic` |
| `wallet.h`, `wallet.cpp` | `Wallet` — наличные участника, свой `std::mutex`, `TrySpend` проверяет и списывает за один вызов |
| `simulation.h`, `simulation.cpp` | `sim::Run` — экономика, ходы участников, режимы single/parallel, флаг остановки |
| `main.cpp` | разбор аргументов, обработчик Ctrl+C, печать итога и проверка правил |
| `tests/bank_tests.cpp` | юнит-тесты `Bank` и `Wallet`, многопоточный тест 8 × 100 000 |

`bank.cpp` и `wallet.cpp` собираются в библиотеку `lab03-bank-core`, к ней линкуются
`bank` и `bank-tests`. Тесты написаны на нескольких макросах в самом файле — внешние
библиотеки не нужны.

## Куда текут деньги

```
Электростанция (счёт) --зарплата--> Отец (счёт) --снял--> Отец (кошелёк) --дал--> Мать, Сын, Дочь
        ^                                |                                            |
        |                         за электричество                                покупки
        |                                v                                            v
        +------------ за электричество ----------- Продавец (счёт) <--выручка-- Продавец (кошелёк)
```

Банк умеет только класть и снимать, поэтому перевод «со счёта на счёт» идёт через
кошелёк того, кто платит: `TryWithdrawMoney` → `Wallet::Add` → `Wallet::TrySpend` →
`DepositMoney`. Если денег не хватает, участник пропускает ход.

## Ключевые моменты

- **Один мьютекс на весь банк.** Наличные и балансы связаны правилом «сумма не
  меняется», поэтому меняются вместе, под одним захватом.
- **Сначала проверки, потом изменения.** Метод бросает исключение до того, как что-то
  поменял, — банк остаётся прежним, а `std::lock_guard` отпускает мьютекс в деструкторе.
- **`TryWithdrawMoney` вместо `GetAccountBalance` + `WithdrawMoney`.** Проверка и
  списание в одном вызове — между ними никто не вклинится.
- **Счётчик операций — `std::atomic`.** Он ни с чем не связан правилом, поэтому
  мьютекс ему не нужен; увеличивается в начале каждого метода, в том числе неудачного.
- **Кошельки.** У каждого свой мьютекс; два мьютекса кошельков никогда не держатся
  одновременно (сначала `TrySpend` у одного, потом `Add` у другого), поэтому
  взаимной блокировки нет.
- **Остановка.** Обработчик Ctrl+C только пишет `true` в `sim::g_stopRequested`;
  участники проверяют флаг перед каждым ходом. В режиме parallel главный поток следит
  за временем и тоже ставит флаг, деструкторы `jthread` дожидаются всех.
- **Проверка правил — после завершения всех потоков**: пока участники работают,
  часть денег «в пути» между кошельком и банком.
