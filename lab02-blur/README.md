# Лабораторная 2 — размытие BMP в N потоках

Программа читает BMP, размывает его box-фильтром в N потоках и записывает результат.
Каждый выходной пиксель — среднее по квадрату (2r+1)×(2r+1) вокруг него; за краем
изображения берётся ближайший пиксель края.

```
./build/lab02-blur/lab02-blur <input.bmp> <output.bmp> <threads> <h|v|s> [radius=5]
```

Схема деления изображения между потоками:

- `h` — N горизонтальных полос;
- `v` — N вертикальных полос;
- `s` — сетка N×N прямоугольников, каждому потоку по N штук (по одному в каждой
  строке и каждом столбце сетки).

Поддерживаются несжатые BMP 24 и 32 бита на пиксель; результат — 24 бита.

На stdout выводится одна CSV-строка:

```
threads,split,radius,hardware_concurrency,ms
```

`ms` — время только обработки: чтение и запись файла в замер не входят.

## Замеры

`bench.sh` (Linux/WSL) прогоняет программу на 1–4 ядрах (через `taskset`) для
1–16 потоков, по 5 повторов, и собирает CSV для графиков T, S = T₁/T_N, E = S/N:

```
./lab02-blur/bench.sh ./build/lab02-blur/lab02-blur input.bmp h 15 > results.csv
```

На Windows число ядер ограничивается через `start /affinity <маска>`
(1, 3, 7, F — одно, два, три, четыре ядра).

## Ключевые моменты

- Потоки читают только из исходного изображения и пишут только в свои пиксели
  результата — области записи не пересекаются, поэтому синхронизация не нужна.
- Границы частей считаются как `size * i / n`: части отличаются не больше чем на
  один пиксель, при N больше размера изображения часть может быть пустой — это
  корректно.
- Каждому потоку его список прямоугольников передаётся перемещением, исходное
  изображение — через `std::cref`, результат — через `std::ref`.
- `std::jthread` в векторе: выход из блока дожидается всех потоков, после чего
  останавливается таймер.
